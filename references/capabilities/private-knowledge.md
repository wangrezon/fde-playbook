# 私有知识四步转化

## R — 原文 (Reading)

> 第一步，抽取。……第二步，脱敏。把客户标识、具体数字、可回溯的细节去掉，只留下规律本身。……第三步，结构化。……第四步，入库。
>
> — 曹犟，第 14 讲

## I — 方法论骨架 (Interpretation)

把现场 know-how 从「脑子里」变成「公司资产」四步，各步都有误区：

1. **抽取**：靠项目沉淀清单、复盘、结构化访谈及时抽出。专家往往说不清直觉，要靠交互记录捞默会知识——拒绝理由和争论过程是老师傅在教 Agent。
2. **脱敏**：去掉客户标识、具体数字、可回溯细节，只留规律。用「边界三问」验收——拿给同行下一家客户看原客户会不会觉得泄密？有没有能回溯到具体企业的数字/名称/组织细节？描述的是行业怎么运行还是这家企业怎么运行？
3. **结构化**：拆成三种 AI 可用形态——Context（背景知识）、Skill（操作性知识）、Workflow（流程性知识）。
4. **入库**：纳入分层知识库，被版本管理、被评估集覆盖、持续迭代。

四个误区：堆文档不等于积累知识、只抹名字等于没脱敏、塞原始文档不等于结构化、没人更新则入库即巅峰。

## A1 — 应用示例 (Application Example)

### 示例 1：英雄工程师（反例）
- **类型与来源**: 原书反例，第 18 讲
- **问题/输入**: 关键经验和做法只存在某个人身上，「这个客户只有老王能处理」被当表扬
- **方法论的使用**: 用四步转化反查——没做抽取/脱敏/结构化/入库，能力锁死在个人身上
- **结论**: 人成了系统的单点故障，越依赖越不沉淀，越不沉淀越依赖
- **结果**: 未说明（作为失败模式）

### 示例 2：排期优化 know-how 转化（合成演练，规则可复算）
- **类型与来源**: 原书未提供完整案例，以下为合成演练
- **问题/输入**: 客户现场有一条「排期要提前两小时设置」的 know-how
- **方法论的使用**: 抽取（沉淀清单记录）→脱敏（去客户名与具体时间，过边界三问）→结构化（Context 口径 + Skill 标准做法 + Workflow 业务目标）→入库（版本管理 + 评估集覆盖）
- **结论**: 从个人经验变成可跨客户共享的行业规律
- **结果**: 合成演练输出，非作者经历

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. 项目做完了，经验只留在几个人的脑子里，想沉淀下来
2. 要建立「从现场到知识库」的转化机制
3. 担心「把客户数据/隐私带出门」，不知道知识怎么脱敏
4. 想判断一条现场经验能不能跨客户共享

### 语言信号 (用户的话里出现这些就应激活)

- 「怎么把经验沉淀成知识」「私有知识怎么抽出来」「脱敏怎么做」
- 「边界三问」「Context/Skill/Workflow」「默会知识怎么捞」
- 英文: "knowledge asset", "extract desensitize structure", "tacit knowledge", "boundary questions"

### 与相邻 skill 的区分

- 与 `knowledge-layering` 的区别：本卡是「把 know-how 变成知识资产的工艺」，knowledge-layering 是「知识库的四层结构」。
- 与 `sediment-pipeline` 的区别：本卡沉淀「知识」，sediment-pipeline 沉淀「产品能力」。

## E — 可执行步骤 (Execution)

**必需输入**: 现场行业认知/默会知识 + 交互记录。缺「及时性」时先建立沉淀清单/复盘/访谈机制，aha moment 过三个月就忘。

**交付物与完成标准**: 进入分层知识库的结构化知识资产（被版本管理 + 评估集覆盖）。

1. **抽取**
   - 完成标准: 从沉淀清单/复盘/访谈/交互记录中抽出规律，含默会知识（拒绝理由、争论过程）。
2. **脱敏**
   - 完成标准: 去客户标识与可回溯细节，过边界三问。
3. **结构化**
   - 完成标准: 拆成 Context / Skill / Workflow 三种形态之一。
4. **入库**
   - 完成标准: 纳入分层知识库，版本管理 + 评估集覆盖 + 持续迭代。

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- 要沉淀「产品能力」而非「知识」——那是 sediment-pipeline 的职责
- 要组织知识库结构——那是 knowledge-layering 的职责
- 涉及客户原始数据/明细（用户明细、订单记录属客户）——那些不能「转化」，只能留在客户环境

### 作者在书中警告的失败模式

- 四个误区：堆文档≠积累知识、只抹名字≠脱敏、塞原始文档≠结构化、没人更新则入库即巅峰。
- 私有知识的「私有」相对同行、不是相对客户——企业特有知识「一个字都不能带出门」。

### 作者的盲点 / 时代局限

- 边界三问的通过/不通过判例作者未给刻度，脱敏程度靠判断——需自行积累判例。

### 容易混淆的邻近方法论

- 「私有知识」≠「客户数据」：私有知识是从大量项目提炼的行业规律（可跨客户共享），客户数据是企业特有的（不能出门）。
