# 定价（OLA + RaaS + 客单价匹配）

## R — 原文 (Reading)

> 这份协议需要写清楚四件事：这次交付要产出什么结果，怎么衡量，谁对衡量负责，审核节奏是什么。
>
> — 曹犟，第 15 讲

## I — 方法论骨架 (Interpretation)

按工具卖，FDE 必然沦为成本中心；把业务结果写进合同，才能从「成本」变「收入」。两块拼图：

**OLA（结果级协议）**：FDE 与客户之间的书面结果级协议，写清四要素——产出什么结果（用客户业务语言，非 FDE 黑话）、怎么衡量（北极星 + 基线 + 归因，精确到公式）、谁对衡量负责（落到具名负责人）、审核节奏（按指标变化周期定期看曲线，不等于每周 demo）。本质不是记分卡，是信任机制：既写供应商承诺，也写客户配合义务。

**收费方式三种 + 客单价匹配**：①打包进平台订阅（简单但人力成本不消失、毛利随客户数下降）；②单独专业服务收费（可核算但激励多卖人天、抑制沉淀）；③OLA + 效果分成（价值对齐最好但衡量纪律要求最高）。按客单价匹配——轻 FDE（几十万，标准产品+行业模板，远程为主，订阅定价）、中 FDE（几百万，关键场景驻场，基础费+效果分成）、重 FDE（数千万以上，全周期嵌入，提高效果分成比重甚至深度对赌）。最贵错配是「拿几十万客单价维持全周期重驻场」。

## A1 — 应用示例 (Application Example)

### 示例 1：客单价错配（合成演练，规则可复算）
- **类型与来源**: 原书给出匹配表、未给完整案例，以下为合成演练
- **问题/输入**: 某团队拿几十万客单价却维持全周期驻场的重 FDE
- **方法论的使用**: 按匹配表反查——几十万对应轻 FDE（标准产品+模板+远程），全周期驻场是数千万级的重 FDE
- **结论**: 最贵错配，人力成本跑赢毛利
- **结果**: 合成演练输出，非作者经历

### 示例 2：写一份 OLA（合成演练，规则可复算）
- **类型与来源**: 原书未提供完整 OLA 范文，以下为合成演练
- **问题/输入**: 与中型客户约定「提高广告 ROI」的交付
- **方法论的使用**: OLA 四要素——结果（用客户业务语言写 ROI 目标）、衡量（北极星+基线+归因公式）、负责人（具名）、审核节奏（按指标变化周期）
- **结论**: 从「一次签字验收」变成「定期看曲线」
- **结果**: 合成演练输出，非作者经历

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. 要跟客户谈 FDE 项目的报价方式
2. 团队总被当「卖人天」，想转成「卖结果」
3. 要写一份能验收、能分成的合同/协议
4. 拿到的客单价和投入深度不匹配，想纠偏

### 语言信号 (用户的话里出现这些就应激活)

- 「FDE 怎么定价」「OLA 怎么写」「按人天还是按结果收费」
- 「RaaS」「基础费加效果分成」「客单价和投入深度怎么匹配」
- 英文: "outcome level agreement", "result as a service", "pricing model", "value-based pricing"

### 与相邻 skill 的区分

- 与 `translation-northstar` 的区别：本卡用「翻译+北极星」的产出写进 OLA，但还涉及收费方式与客单价匹配，超出前者范围。
- 与 `service-trap` 的区别：本卡是「怎么收费」，service-trap 是「怎么不滑向外包」——定价方式（人天 vs 效果）直接影响是否会滑向服务陷阱。

## E — 可执行步骤 (Execution)

**必需输入**: 客单价量级 + 驻场深度 + 可复用能力 + 北极星/基线/归因口径。缺「北极星与归因」时先回到 translation-northstar 补齐，否则 OLA 无法衡量。

**交付物与完成标准**: 一份 OLA（四要素）+ 与客单价匹配的收费方式与 FDE 模式。

1. **定客单价 → FDE 模式**
   - 完成标准: 几十万/几百万/数千万分别对应轻/中/重 FDE，模式与客单价匹配。
2. **选收费方式**
   - 完成标准: 订阅/专业服务/效果分成三选一或组合，说明代价。
3. **写 OLA 四要素**
   - 完成标准: 结果（客户业务语言）/衡量（公式）/负责人（具名）/审核节奏（按指标周期）齐备。
4. **写双方义务**
   - 完成标准: 合同既写供应商承诺，也写客户配合（数据/权限/流程/决策）。

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- 还没定北极星与归因口径——那是 translation-northstar 的职责
- 要判断公司是否滑向服务陷阱——那是 service-trap 的职责
- 客单价/投入匹配不清、无效果数据可衡量——先补衡量基础

### 作者在书中警告的失败模式

- 按人天收费会锁定外包定价逻辑：激励多卖人天、抑制沉淀，FDE 沦为成本中心。
- 最贵错配：拿几十万客单价维持全周期重驻场。

### 作者的盲点 / 时代局限

- 轻/中/重的精确金额分界、效果分成比例区间作者未给（仅举例「增量分你 10%」），需自行定档并声明。

### 容易混淆的邻近方法论

- OLA ≠ 按功能验收的传统合同：OLA 写「结果+衡量+负责人+审核节奏」，用客户业务语言，避免「价值难衡量、责任无法界定、风险全在客户」三宗罪。
