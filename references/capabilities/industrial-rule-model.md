# 制造/能源：规则/模型划界 + 数据地基

## R — 原文 (Reading)

> 确定性归规则，概率归模型。第一问：这个环节有没有唯一正确答案？第二问：错了能不能低成本回退？第三问：答案会不会随现场条件而改变，而且变化规律说不清？
>
> — 曹犟，第 20 讲

## I — 方法论骨架 (Interpretation)

重资产行业（制造/能源）里，物理世界不太接受「大概率对」，概率模型输出必须过确定性闸门才能碰物理世界。两个工具：

**规则/模型三步划界**：①有没有唯一正确答案？有就归规则（工艺参数上下限硬校验）；②错了能不能低成本回退？能回退的模型先给建议人选，不能回退的模型输出只当参考、最终动作必须过规则闸门；③答案是否随现场条件变且规律说不清？会才轮到模型上场（参数寻优）。安全红线的判断权永远在人。

**数据地基三检查**：①北极星指标的每个数字能否从源系统一路追到报表；②跨系统同一实体两边编号能否对上；③老师傅手工维护的 Excel 字段进系统了没有。三问都通过数据地基才合格，有一问不过先补地基再谈上线扩展。

## A1 — 应用示例 (Application Example)

### 示例 1：丰田自动织机涂装缺陷（转述）
- **类型与来源**: 原书转述，第 20 讲
- **问题/输入**: 保险杠涂装缺陷返工成本高
- **方法论的使用**: 3 个月试点连接设备传感器/工艺/温湿度数据，分析近 400 个变量找缺陷根因，再让生产、工艺团队基于同一数据采取措施
- **结论**: 制造业「提质」级价值，验收看良率/缺陷率而非模型准确率
- **结果**: 特定涂装缺陷降约 25%，分析周期从 5 天缩到 4 小时以内

### 示例 2：工艺参数优化划界（合成演练，规则可复算）
- **类型与来源**: 原书未提供完整案例，以下为合成演练
- **问题/输入**: 制造场景要做工艺参数优化
- **方法论的使用**: 参数上下限→归规则硬校验；排产建议→模型先给候选、人挑；数据地基三问逐查
- **结论**: 概率模型输出过确定性闸门才能碰物理世界
- **结果**: 合成演练输出，非作者经历

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. 在制造/能源行业落地 AI，纠结「用规则还是用模型」
2. 客户说「AI 建议不错但不敢直接执行」，要设计人机分工
3. 发现数据基础差、分析结果不可信，想定位地基裂缝
4. 判断哪些环节能全自动、哪些必须人把关

### 语言信号 (用户的话里出现这些就应激活)

- 「确定性归规则概率归模型」「什么时候用规则什么时候用模型」「安全红线」
- 「数据地基三检查」「数据能不能追源」「老师傅的 Excel」
- 英文: "rules vs model", "deterministic vs probabilistic", "data foundation", "industrial AI"

### 与相邻 skill 的区分

- 与 `regulated-industry` 的区别：本卡对应制造/能源，regulated-industry 对应金融/政企/医疗——同属行业落地，方法不同。
- 与 `go-live` 的区别：本卡是「行业里的规则/模型分工 + 数据地基」，go-live 是「通用上生产检查」。
- 与 `customer-service-authorization` 的区别：本卡是「物理世界的规则闸门」，后者是「客服业务授权等级」。

## E — 可执行步骤 (Execution)

**必需输入**: 目标环节 + 是否有唯一正确答案 + 回退成本 + 现场条件变化规律。缺「回退成本」判断时先问「这一步做错了能不能低成本撤销」。

**交付物与完成标准**: 每个环节的「规则/模型/人」分工 + 数据地基三检查结论。

1. **三步划界**
   - 完成标准: 每个环节回答「有无唯一正确答案 / 错了能否回退 / 是否随现场条件变」，归入规则/模型/人。
2. **设规则闸门**
   - 完成标准: 概率模型输出过确定性闸门才能执行，安全红线判断权在人。
3. **数据地基三检查**
   - 完成标准: 数字追源/跨系统编号/老师傅 Excel 三问逐查，任一不过先补地基。

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- 非制造/能源的重资产场景（无物理约束/安全红线）——划界的紧迫性不同
- 要过整体上线检查——那是 go-live 的职责
- 客服/零售类业务授权——那是 customer-service-authorization 的职责

### 作者在书中警告的失败模式

- 数据基础比模型更难：老师傅手工维护的 Excel 字段没进系统，最值钱的判断逻辑就留在个人电脑里。

### 作者的盲点 / 时代局限

- 数据地基三检查是「合格/不合格」的定性判据，未给「补到什么程度算够」的量化标准，需按场景自行定。

### 容易混淆的邻近方法论

- 「规则/模型划界」与「HITL 三级」是不同层面的分工：前者是「哪个环节用规则/模型」，后者是「Agent 动作分几级人工确认」。
