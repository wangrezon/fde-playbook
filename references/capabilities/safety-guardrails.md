# 安全护栏五件套

## R — 原文 (Reading)

> 第一，字段级权限控制。第二，明细数据脱敏设置。第三，操作白名单和最小权限设置。第四，审计机制。第五，回执确认与可回滚机制。
>
> — 曹犟，第 10 讲

## I — 方法论骨架 (Interpretation)

AI 是放大器——既放大效率，也放大小疏忽。自然语言查询让「一句话就能把数据问出来」，任何权限缺陷都会被迅速放大。上线前逐项检查五件套：

1. **字段级权限控制**：Agent 数据访问继承提问者本人权限，精确到字段，提问者看不到的 Agent 也不能看；
2. **明细数据脱敏设置**：汇总可答，明细是否脱敏要设；
3. **操作白名单 + 最小权限**：只给完成任务所需的最小权限，不加任何额外权限；
4. **审计机制**：每次回答和操作都留痕，出问题能查到哪一步、什么原因；
5. **回执确认 + 可回滚**：执行前展示动作给用户确认，执行错能回滚；不可回滚的操作默认不进自动执行白名单。

核心原则：合规和访问控制做进配置，能力长在产品里而非人身上；权限跟着自主权走，自主权升一级、护栏加一层。

## A1 — 应用示例 (Application Example)

### 示例 1：「问题答对却越权」（反例）
- **类型与来源**: 原书反例，第 10 讲
- **问题/输入**: Agent 回答质量没问题，但把提问者无权查看的明细数据一并展示出来
- **方法论的使用**: 用五件套反查——缺了字段级权限 + 明细脱敏，越权数据被 AI 一句话问出
- **结论**: 传统界面权限靠「一个界面一个界面翻」天然约束，自然语言查询打破了这个约束，权限缺陷被放大
- **结果**: 未说明（作为数据安全红线论证）

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. 一个能查数据/做操作的 Agent 要上线
2. 客户/安全部门问「怎么保证 Agent 不越权」
3. 要设计 Agent 的权限与审计方案
4. Agent 已出过数据泄露/越权事故，要补护栏

### 语言信号 (用户的话里出现这些就应激活)

- 「Agent 上线要配什么安全措施」「字段级权限怎么设」「明细数据要不要脱敏」
- 「怎么防止 Agent 越权」「操作白名单」「审计留痕怎么设」
- 英文: "agent guardrails", "field-level permission", "data masking", "audit trail", "rollback"

### 与相邻 skill 的区分

- 与 `knowledge-layering` 的区别：本卡管「权限与安全红线」，后者管「知识结构」。
- 与 `go-live` 的区别：本卡的五件套是 go-live「六项检查」里第三项「安全与权限」的展开，go-live 是总闸门。
- 与 `customer-service-authorization` 的区别：本卡是「数据/操作安全护栏」，后者是「客服业务授权等级（答得准/能动手/敢托付）」——后者是前者的一个应用场景。

## E — 可执行步骤 (Execution)

**必需输入**: Agent 要访问的数据范围 + 要执行的操作清单。缺「操作清单」时先枚举 Agent 所有可能的动作，不遗漏「花钱/改数据」类高风险动作。

**交付物与完成标准**: 一张五件套逐项检查表，每项有配置结论（通过/待配）。

1. **字段级权限**
   - 完成标准: Agent 访问数据继承提问者权限、精确到字段。
2. **明细脱敏**
   - 完成标准: 汇总可答、明细脱敏规则明确。
3. **白名单 + 最小权限**
   - 完成标准: 只授完成任务所需最小权限，无额外权限。
4. **审计**
   - 完成标准: 每次回答/操作留痕，可回溯到步骤与原因。
5. **回执确认 + 回滚**
   - 完成标准: 高风险动作执行前确认；不可回滚操作不进自动白名单。

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- 要组织知识结构——那是 knowledge-layering 的职责
- 要做整体上线六项检查——那是 go-live 的职责（本卡是其中一项的展开）
- 纯内部分析、无权限边界的数据处理——五件套按需裁剪，不机械套全

### 作者在书中警告的失败模式

- 「问题答对却越权」：只关注回答准不准、不检查越不越权，一次数据泄露就能把信任顶点清零且不可恢复。

### 作者的盲点 / 时代局限

- 护栏「焊死」的成本与上线速度是矛盾，作者强调「第一天焊死」但未给「护栏与迭代速度」的权衡刻度。

### 容易混淆的邻近方法论

- 「回执确认」与 HITL 三级（自动/通知后/确认前）是同一治理逻辑的两层表达：五件套是「安全配置」，HITL 是「授权分级」。
