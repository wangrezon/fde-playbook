# 四层知识库

## R — 原文 (Reading)

> 第一层，产品使用知识：某个功能怎么用、参数是什么意思。……第二层，跨行业共性知识……第三层，行业特有知识……第四层，企业特有知识：这家客户的指标定义、业务术语、组织架构。
>
> — 曹犟，第 10 讲

## I — 方法论骨架 (Interpretation)

Agent 的引擎在知识库。分散知识按四层组织，每层难度与价值递增：

1. **产品使用知识**（最标准）：功能怎么用、参数含义；
2. **跨行业共性知识**（通用方法论）：用户生命周期、RFM 模型；
3. **行业特有知识**：电商 GMV 口径、金融合规要求；
4. **企业特有知识**（最难获取但最有价值）：这家客户的指标定义、业务术语、组织架构。

关键判断是「模型已经够聪明，真正的天花板是知识结构」——同一 Agent 内部 99%、客户环境 90% 的差异，主要来自知识库与口径成熟度，而非模型能力。每条知识还要标四类维护信息：来源、负责人、适用范围、更新时间。度量 Agent 好坏的四项指标是：查询/创建成功率、平均响应时间、用户转化率、满意度。

## A1 — 应用示例 (Application Example)

### 示例 1：MetricAgent 内部 99% vs 客户 90%（作者亲历）
- **类型与来源**: 原书亲历，第 10 讲
- **问题/输入**: 同样 Agent、同样模型，内部准确率 99%，客户环境掉到 90%
- **方法论的使用**: 用四层知识库定位差距——中间 9 个百分点差在客户知识库与指标口径成熟度，模型能力不是主要矛盾
- **结论**: 换模型无济于事，补企业特有层的指标口径与业务术语才是关键
- **结果**: 差距被归因于知识库与口径成熟度（未给改善后量化结果）

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. Agent 在客户环境表现远差于内部，想定位原因
2. 要把一堆文档/知识组织成 Agent 能用的知识库
3. 客户说「Agent 答得不对」，但不知道是模型问题还是知识问题
4. 想建立知识库的维护规范（来源/负责人/更新时间）

### 语言信号 (用户的话里出现这些就应激活)

- 「知识库怎么分层」「为什么客户环境准确率掉」「Agent 天花板是模型还是知识」
- 「怎么组织知识给 Agent 用」「指标口径怎么管」
- 英文: "knowledge base layers", "agent knowledge structure", "accuracy drop in production", "domain knowledge"

### 与相邻 skill 的区分

- 与 `private-knowledge`（私有知识四步）的区别：本卡是「知识库的结构分层」，后者是「把现场 know-how 抽成知识资产的四步工艺」。
- 与 `safety-guardrails` 的区别：本卡管「知识」，后者管「权限与安全」——同属第 10 讲的「用 AI 放大交付」，但一个是内容、一个是红线。

## E — 可执行步骤 (Execution)

**必需输入**: 当前知识现状 + Agent 的失效样例。缺「失效样例」时先收集「客户问了什么、答错了什么」，不凭感觉分层。

**交付物与完成标准**: 一份四层知识库结构 + 每层内容 + 每条知识的四类维护信息。

1. **按四层归类现有知识**
   - 完成标准: 每条知识归入产品使用/跨行业共性/行业特有/企业特有之一。
2. **定位天花板**
   - 完成标准: 能指出「模型能力 vs 知识结构」哪个是当前瓶颈（如客户 90% 差在企业特有层口径）。
3. **补企业特有层**
   - 完成标准: 指标定义/业务术语/组织架构有明确来源与口径管理。
4. **标四类维护信息**
   - 完成标准: 每条知识有来源/负责人/适用范围/更新时间。

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- 要把现场 know-how 抽成知识资产——那是 private-knowledge 的职责（本卡只管「结构」）
- 要配置权限与安全护栏——那是 safety-guardrails 的职责
- 纯粹选模型/调 prompt、知识库已成熟——本卡针对「知识结构」而非模型

### 作者在书中警告的失败模式

- 把所有文档堆进一个库不分层：把企业特有知识当共享知识带出，护城河变成事故现场（对应 private-knowledge 的边界三问）。

### 作者的盲点 / 时代局限

- 「天花板是知识结构」的结论依赖 MetricAgent 单一样本（99% vs 90%），对知识已高度标准化的场景，模型能力可能重新成为瓶颈。

### 容易混淆的邻近方法论

- 四层知识库与「私有知识边界三问」是上下层关系：边界三问决定一条知识能不能跨客户共享（进上三层还是留企业层）。
